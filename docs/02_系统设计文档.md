# 识忆承缘系统设计文档

## 1. 总体架构

系统采用前后端分离架构，前端负责页面展示和用户交互，后端负责业务逻辑、数据持久化、AI 调用和权限控制。

```text
用户浏览器
  ↓
Vue 前端
  ↓
Nginx 前端容器
  ↓ /api
Spring Boot 后端容器
  ↓
MySQL / Redis / DashScope 大模型
```

线上部署链路：

```text
用户访问域名
  ↓
Cloudflare
  ↓
Caddy HTTPS 反向代理
  ↓
Docker Compose
  ├── frontend：Nginx + Vue 静态资源
  ├── backend：Spring Boot 应用
  ├── mysql：业务数据库
  └── redis：缓存和向量检索
```

## 2. 模块划分

### 2.1 前端模块

前端路径：

```text
frontend/relationship-agent-web
```

主要模块：

- 登录注册页面
- 首页控制台
- AI 聊天页面
- 人物管理页面
- 人物详情页面
- 知识库管理页面
- 图片分析页面
- 意见收集箱页面
- 管理员后台页面
- 迭代计划页面
- 个人中心页面

### 2.2 后端模块

后端路径：

```text
back/demo1
```

主要模块：

- Controller：接收前端请求
- Service：处理业务逻辑
- Mapper：操作 MySQL 数据库
- POJO/DTO：数据对象
- Interceptor：登录拦截和 JWT 校验
- AOP：操作日志记录
- Config：跨域、Swagger、模型、Redis 等配置

### 2.3 数据层模块

MySQL 保存业务数据：

- 用户
- 人物档案
- 人物记忆
- 聊天会话
- 聊天消息
- 知识库文档
- 知识库分片
- 意见反馈
- 操作日志

Redis 保存：

- 验证码
- 临时缓存
- 向量数据
- LangChain4j 相关记忆或检索数据

## 3. 接口设计

系统接口以 REST 风格为主，前端通过统一 request 封装调用后端接口。

典型接口类型：

```text
POST /api/login                 用户登录
POST /api/register              用户注册
GET  /api/user/me               获取当前用户
GET  /api/persons               查询人物列表
POST /api/persons               新增人物
PUT  /api/persons/{id}          修改人物
DELETE /api/persons/{id}        删除人物
GET  /api/chat-sessions         查询聊天会话
POST /api/chat                  发送 AI 对话
GET  /api/knowledge             查询知识库
POST /api/knowledge/text        新增知识
POST /api/knowledge/upload      上传知识文件
POST /api/image/analyze         图片分析
GET  /api/admin/users           管理员查询用户
GET  /api/admin/logs            管理员查询日志
```

接口文档由 Swagger/OpenAPI 自动生成。

本地访问：

```text
http://localhost:8080/swagger-ui/index.html
```

服务器访问：

```text
http://服务器IP:8081/swagger-ui/index.html
```

## 4. 数据流转

### 4.1 登录鉴权流程

```text
用户输入账号密码
  ↓
前端请求登录接口
  ↓
后端校验密码
  ↓
生成 JWT Token
  ↓
前端保存 Token
  ↓
后续请求自动携带 Authorization
  ↓
后端拦截器解析 Token 获取 userId
```

### 4.2 AI 聊天流程

```text
用户发送问题
  ↓
前端携带 token 和 sessionId 请求后端
  ↓
后端获取 userId 和当前会话
  ↓
检索人物记忆、聊天历史和知识库内容
  ↓
拼接上下文请求大模型
  ↓
保存用户消息和 AI 回复
  ↓
返回回答给前端
```

### 4.3 知识库入库流程

```text
用户上传文档或手动录入文本
  ↓
后端保存 knowledge_document
  ↓
文本切分为多个 chunk
  ↓
调用 Embedding 模型生成向量
  ↓
向量写入 Redis
  ↓
chunk 元数据写入 MySQL
```

### 4.4 知识库检索流程

```text
用户提问
  ↓
问题生成 Embedding
  ↓
Redis 向量相似度检索
  ↓
根据 embeddingId 回查 MySQL chunk
  ↓
得到相关知识片段
  ↓
作为上下文交给大模型
```

### 4.5 图片分析流程

```text
用户上传图片
  ↓
前端以 FormData 提交
  ↓
后端校验文件大小和类型
  ↓
调用视觉模型分析图片
  ↓
返回图片描述、文字提取或关系信息
  ↓
用户可根据结果补充人物记忆
```

### 4.6 操作日志流程

```text
用户调用关键业务接口
  ↓
方法上标记 @OperationLog
  ↓
AOP 切面拦截方法执行
  ↓
记录用户、操作名称、时间、结果
  ↓
写入操作日志表
```

## 5. 关键技术实现

### 5.1 JWT 登录拦截

后端通过拦截器统一校验登录态。请求进入 Controller 前，拦截器读取请求头 Authorization，解析 JWT，取得 userId 并放入 request attribute，业务接口再根据 userId 查询当前用户数据。

### 5.2 BCrypt 密码加密

用户密码不直接明文保存。注册时使用 BCrypt 加密密码，登录时使用 BCrypt 校验原始密码和加密后的 password_hash。

### 5.3 RAG 知识库问答

系统通过“知识切分 + Embedding + Redis 向量检索 + 大模型生成”的方式实现 RAG。相比直接问大模型，RAG 能让回答结合用户自己的知识库内容。

### 5.4 LangChain4j 模型接入

后端通过 LangChain4j 接入兼容 OpenAI 协议的 DashScope 模型，用于聊天、Embedding 和图片分析等能力。

### 5.5 AOP 操作日志

系统定义操作日志注解，在关键方法上标记业务操作名称。AOP 切面统一记录日志，减少业务代码重复。

### 5.6 Swagger/OpenAPI

系统集成 SpringDoc OpenAPI，启动后自动扫描 Controller，生成可视化接口文档，方便评审和开发者验证接口。

### 5.7 Docker Compose 部署

通过 Docker Compose 编排前端、后端、MySQL 和 Redis，使项目可以稳定部署到云服务器。
