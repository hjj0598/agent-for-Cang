# 仓颉候选记忆规则检测模块说明

## 1. 模块定位

仓颉模块名称：

```text
cangjie-memory-guard
```

所在位置：

```text
back/demo1/cangjie-memory-guard
```

模块定位：

> 仓颉候选记忆规则检测模块是系统的可插拔增强模块，用于在 AI 抽取候选记忆之后，对记忆内容进行规则化初筛，识别偏好变化、否定偏好、时间变化和冲突风险。

## 2. 为什么不重写 Java 后端

系统主后端采用 Java Spring Boot，承担用户、人物、记忆、聊天、图片分析、知识库和后台管理等核心业务。如果为了使用仓颉而重写主后端，会显著增加工程风险。

因此本项目采用更稳妥的工程方案：

```text
Java Spring Boot 主服务负责核心业务闭环。
仓颉模块负责候选记忆规则检测。
二者通过 HTTP 接口解耦。
```

这种方式的优势：

1. 不破坏原有 Java 主系统。
2. 仓颉模块可单独运行、单独测试。
3. 仓颉服务不可用时，Java 后端自动降级。
4. 评审时可以清楚展示仓颉在系统中的具体作用。

## 3. 调用流程

```text
AI/前端提交候选记忆
        ↓
Java 后端创建候选记忆
        ↓
调用 CangjieMemoryGuardService
        ↓
POST http://localhost:9001/analyze-memory
        ↓
仓颉模块返回规则检测结果
        ↓
Java 后端补全 memoryType、trustLevel、confidence、riskLevel
        ↓
候选记忆进入收件箱，由用户确认
```

## 4. 接口说明

请求地址：

```text
POST http://localhost:9001/analyze-memory
```

请求示例：

```json
{
  "content": "JJKING 最近不喜欢喝咖啡了"
}
```

响应示例：

```json
{
  "memoryType": "DISLIKE",
  "trustLevel": "MEDIUM",
  "factType": "AI_EXTRACTED_FACT",
  "confidence": 0.86,
  "riskLevel": "HIGH",
  "needsReview": true,
  "hasTemporalChange": true,
  "hasConflictRisk": true,
  "reason": "仓颉规则检测：包含时间变化词和否定偏好词，可能是偏好变化或冲突记忆，建议进入候选记忆收件箱由用户确认。"
}
```

## 5. Java 接入位置

Java 调用服务：

```text
back/demo1/src/main/java/com/example/demo/service/CangjieMemoryGuardService.java
```

候选记忆接入点：

```text
back/demo1/src/main/java/com/example/demo/service/impl/MemoryCandidateServiceImpl.java
```

配置项：

```properties
app.cangjie.memory-guard.enabled=false
app.cangjie.memory-guard.url=http://localhost:9001/analyze-memory
app.cangjie.memory-guard.timeout-ms=800
```

## 6. 降级机制

仓颉服务失败时，Java 后端不会中断主流程。

降级逻辑：

```text
仓颉未启用 / 服务未启动 / 接口超时 / 返回异常
        ↓
CangjieMemoryGuardService 返回 null
        ↓
MemoryCandidateServiceImpl 继续使用原 Java 候选记忆构建逻辑
        ↓
字段缺失时使用 Java 默认值
```

这种设计保证：

1. 主系统稳定运行。
2. 仓颉模块作为增强能力存在。
3. 比赛演示时可以根据环境选择稳定模式或增强模式。

## 7. 答辩表述

推荐表述：

> 我没有把主后端强行改写成仓颉，因为综合系统赛道更重视完整性和稳定性。我的做法是将仓颉用于更适合它发挥价值的可信记忆治理层，也就是候选记忆规则检测模块。该模块以旁路服务形式参与候选记忆的风险识别，即使服务不可用，系统也会自动降级，不影响核心功能。

一句话亮点：

> 仓颉模块让系统从“能记忆”进一步升级为“可信地记忆”。
