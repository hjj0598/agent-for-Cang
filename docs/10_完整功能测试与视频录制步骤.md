## 2. 验收前准备

### 2.1 检查容器状态

服务器执行：

```bash
cd /opt/relationship-agent
docker compose ps
```

期望结果：

```text
relationship-mysql       Up
relationship-redis       Up
relationship-backend     Up
relationship-frontend    Up
```

判定：

| 结果 | 结论 |
| --- | --- |
| 四个容器均 Up | 可以继续测试 |
| backend 不是 Up | 查看 `docker logs relationship-backend` |
| frontend 不是 Up | 查看 `docker logs relationship-frontend` |
| mysql/redis 不是 Up | 先执行 `docker compose restart mysql redis backend` |

### 2.2 检查前端静态资源

服务器执行：

```bash
curl -I http://127.0.0.1:8088/js/chunk-vendors.8bfd4ea4.js
curl -I http://127.0.0.1:8088/js/app.f7f9ad48.js
curl -I http://127.0.0.1:8088/css/app.b42c87d3.css
```

期望结果：

```text
HTTP/1.1 200 OK
```

如果返回 404，执行：

```bash
docker exec relationship-frontend chmod -R 755 /usr/share/nginx/html
docker compose restart frontend
```

再次检查，直到静态资源返回 200。

## 5. API 级验收命令

以下命令可在浏览器功能异常时辅助定位。

### 5.1 登录接口

```bash
curl -k -X POST https://jj.warwolf.cc.cd/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"演示密码"}'
```

期望：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "token": "...",
    "username": "admin"
  }
}
```

### 5.2 获取当前用户

将登录接口返回的 token 替换到下面命令：

```bash
curl -k https://jj.warwolf.cc.cd/api/user/me \
  -H "Authorization: Bearer TOKEN"
```

期望：

```text
code = 1
```

### 5.3 创建人物

```bash
curl -k -X POST https://jj.warwolf.cc.cd/api/persons \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer TOKEN" \
  -d '{"name":"JJKING","relation":"朋友","description":"比赛演示人物"}'
```

期望：

```text
code = 1
```

### 5.4 创建候选记忆


## 8. 比赛评审建议

答辩时重点讲：

1. 系统不是普通 AI 聊天，而是可信长期记忆智能体。
2. 记忆进入正式库之前经过候选确认。
3. 新旧记忆冲突时不会静默覆盖。
4. AI 回答可以调用人物记忆和知识库。
5. 图片、文档、聊天都能成为关系记忆来源。
6. 仓颉模块用于候选记忆规则检测，是可信治理增强层。

不要重点讲：

1. 只是调用了大模型。
2. 只是做了登录注册。
3. 只是普通 CRUD。

一句话总结：

> 识忆承缘解决的是 AI 长期记忆如何可信进入、如何被用户确认、如何避免冲突、如何服务真实人际关系维护的问题。
